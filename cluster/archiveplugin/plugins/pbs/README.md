# archiveplugin-pbs

replication-manager's Proxmox Backup Server archive plugin (`archive-pbs`): a cluster's
backups kept in a namespace of a PBS datastore. Pure Go, nothing to install on the node:
the PBS protocol (backup and reader sessions over HTTP/2, pxar, dynamic indexes,
client-side encryption compatible with `proxmox-backup-client` key files) comes from
`internal/pbscommon`, a copy of `pbscommon` from RDEM Systems' NimbusBackupClient
(GPL-3.0, source and commit in `internal/pbscommon/NOTICE`). The datastore administration
(snapshot list, notes, forget, prune, namespaces) goes through the PBS REST API.

It is a separate Go module and a separate program, run once per operation as the
contract in `cluster/archiveplugin/wire` says: the request as one JSON document on stdin,
the response as one JSON document on stdout, progress on stderr, secrets in the
environment. `archiveplugin-pbs --manifest` prints its manifest.

## Build

```sh
cd cluster/archiveplugin/plugins/pbs
go build -o archiveplugin-pbs .
```

`make` builds it with the other archive plugins (every `cluster/archiveplugin/plugins/<name>`
with a `go.mod`).

## Settings

| setting       | type   | group    | meaning |
|---------------|--------|----------|---------|
| `base-url`    | string |          | `https://<host>:8007` |
| `datastore`   | string |          | the datastore, created on the PBS by its admin |
| `namespace`   | string |          | the cluster's namespace (`a/b/c`), created by a probe with create; empty: the datastore's root; `remove` needs one |
| `auth-id`     | string |          | the API token, `user@realm!token` |
| `fingerprint` | string |          | the server certificate's SHA-256 fingerprint: pins a self-signed PBS; empty: the certificate is verified as usual |
| `secret`      | secret |          | the API token's secret |
| `encryption-key` | secret |       | a `proxmox-backup-client key create` key file (JSON, or its paper key text). A new archive added without one gets one generated by its probe, stored by replication-manager as this secret (encrypted, never sent back by the API) |
| `encryption-key-password` | secret | | the key's passphrase, when it has one |
| `no-purge`    | bool   |          | the token may not prune: `purge` is a no-op (the PBS's prune job keeps the retention), `forget` is refused |
| `no-modify`   | bool   |          | the token may not modify the datastore: no namespace created by a probe, `remove` refused |
| `no-encrypt`  | bool   |          | a new archive gets no generated key: its snapshots are written in clear on the PBS. An archive without a key and without `no-encrypt` raises WARN0263 |
| `chunk-cache` | int    | advanced | restore: chunks kept in memory (default 16, about 64 MB) |

**Encrypted by default.** On the probe of a new archive (`Request.New`) with no
`encryption-key` and `no-encrypt` off, the plugin generates a key (32 random bytes, no
passphrase, with its fingerprint, the format `proxmox-backup-client` reads) and returns it in
`Response.Secrets`; replication-manager stores it in the archive. Lose it and the snapshots
cannot be restored: keep a copy (the key file, or a paper key printed from it) with the
configuration backup. A key set later encrypts the next snapshots only; PBS keeps both kinds.

Secrets come in `REPMAN_ARCHIVEPLUGIN_SECRET_SECRET`, `..._ENCRYPTION_KEY` and
`..._ENCRYPTION_KEY_PASSWORD`; they are never written in a file nor logged (pbscommon
redacts the token in the requests it logs).

## Operations

| op | does | answers |
|----|------|---------|
| `probe` | lists the namespace's snapshots (server, token, namespace checked); with `create`, creates the missing namespace levels | `created`, `location` |
| `push` | a backup session of the group `host/<backup-id>` (the request's host, characters PBS refuses as `_`): the folder as `backup.pxar` and its catalog, chunks the group's previous snapshot holds not uploaded again; then the notes | `snapshot` (`host/<id>/<time>`) |
| `list` | the namespace's snapshots, newest first | `snapshots` |
| `restore` | a reader session: the archive read chunk by chunk (bounded cache), the files streamed to disk; everything under `target`, or only `include`, kept at its place | `snapshot`, `files` |
| `forget` | deletes a snapshot | `removed` |
| `purge` | PBS prune of each group with the policy's counts (`dryRun` lists) | `removed` |
| `size` | the sum of the namespace's snapshot sizes (logical) | `size` |
| `remove` | deletes the namespace and its groups; refused without a namespace | `location` |
| `sync` | not supported: a copy between PBS datastores is a sync job of the PBS | error |

### Tags

PBS has no tags. The snapshot's host, pushed path and tags are written on the first line of
its notes (`repman host=… path=… tags=…`, URL-escaped), the line the snapshot list returns
as its comment.

### Purge

PBS prunes by counts: `keep-last`, `-hourly`, `-daily`, `-weekly`, `-monthly`, `-yearly`, as
the cluster's `backup-keep-*`. A `backup-keep-within*` window has no PBS equivalent: the
purge is refused, never run with less than the policy. The space comes back with the
datastore's garbage collection, a job of the PBS.

## Tokens per cluster: scripts/

Run by whoever holds an admin API token of the PBS (`PBS_ADMIN_AUTHID`, `PBS_ADMIN_SECRET`
in the environment, sent to curl on its stdin, never on a command line):

- `pbs-cluster-token.sh <base-url> <datastore> <cluster> [user]`: the namespace `<cluster>`,
  the user (default `repman@pbs`) granted `DatastorePowerUser` on it, the token
  `<user>!<cluster>` granted `DatastoreBackup` on it only; prints the archive's settings,
  `no-purge` and `no-modify` on, and the token's secret, once.
- `pbs-cluster-allow-purge.sh <base-url> <datastore> <cluster> [user]`: raises that token to
  `DatastorePowerUser` on its namespace (prune of its own backups); when the admin token may
  not change ACLs, prints the request for the PBS operator with the exact command. Then
  `no-purge = false` on the archive.

## API token privileges

| operations | privilege on `/datastore/<store>[/<namespace>]` |
|------------|------------------------------------------------|
| probe, list, size, push, restore | `Datastore.Backup` (owner of its groups) |
| forget, purge | `Datastore.Prune` or `Datastore.Modify` |
| namespace creation (probe with create), remove | `Datastore.Modify` |

A missing privilege is reported as the PBS answers it (HTTP 403, the privilege named).

## Tested on a PBS (2026-10-20)

Against a hosted PBS with a backup-only token: probe, push (6 MB folder, 1.7 s), a second
push reusing the data chunk, list with the notes decoded, a full restore identical to the
source (`diff -r`), a one-file restore, size. Forget, purge and namespace creation were
refused by the PBS for lack of `Datastore.Prune`/`Modify`, as the table says: to test with
a token holding them. Not tested yet: an encrypted push and restore, the scripts against a PBS with an admin token.
